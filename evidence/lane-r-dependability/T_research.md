# T_research: dependable LLM regeneration of long human-written docs (2026-10-16)
Only what was read this session is cited. "Snippet" = seen only in a search result, not the page. "Not found" = not located.

## 1. Patch/diff edits vs whole-document regeneration
- aider edit formats (https://aider.chat/docs/more/edit-formats.html): whole = full file back (simple, slow, costly); diff = search/replace blocks; udiff = unified diff, adopted for GPT-4 Turbo because it reduced "lazy coding" (elided code replaced by placeholder comments). No numbers on that page.
- aider unified-diffs post (https://aider.chat/docs/unified-diffs.html): 89-task laziness benchmark, gpt-4-1106-preview: search/replace 20% pass, 12 tasks with lazy comments; unified diff 61%, 4 tasks (~3x less laziness). gpt-4-0613: 26% -> 59%. Shows format changes elision rates; vendor-specific, old models.
- aider benchmarks (https://aider.chat/docs/benchmarks.html): whole-file was the most reliable format for GPT-3.5/4 (46%/39% first-try vs diff ~30%/19% on GPT-3.5); the cost of whole is tokens/latency. Counter-evidence: patch formats are not automatically safer; a weak model misuses them.
- Snippet only (https://arxiv.org/pdf/2604.19201 and arXiv 2510.13859 via search): whole-file and search/replace comparable; udiff worst; whole more stable multi-turn. Not read.
- Lost in the Middle (https://arxiv.org/abs/2307.03172): accuracy drops when relevant info is mid-context, even for long-context models. Implication: a 1000-line rewrite is exposed to mid-document loss. No direct "content drop in rewrite" study found.
- OpenAI Predicted Outputs (https://developers.openai.com/api/docs/guides/predicted-outputs): speeds regeneration of mostly-unchanged text; latency only, no fidelity guarantee; rejected tokens are billed; only gpt-4o/4.1 families; no logprobs/tools/n>1. Not applicable to qwen3-next/gpt-oss gateway.
- Anthropic structured outputs (https://platform.claude.com/docs/en/build-with-claude/structured-outputs): constrained decoding guarantees schema validity (not truth); no numeric/length constraints or minItems>1; refusal/max_tokens can break the schema. Page read up to char 100000 only.

## 2. Factuality / entailment of claims vs source
- ALCE (https://arxiv.org/abs/2305.14627): best models leave ~50% of ELI5 answers without full citation support. Citation presence != support.
- Liu et al. verifiability (https://arxiv.org/abs/2304.09848): 4 generative search engines, human eval: only 51.5% of sentences fully supported by their citations (recall), 74.5% of citations support the attached sentence (precision). Direct evidence that "cites a supported fact" gives false comfort.
- FActScore (https://arxiv.org/abs/2305.14251): split long text into atomic facts, score % supported by a knowledge source; automated estimator <2% error vs humans (biographies, retrieval + strong LM). Pip package factscore.
- RAGAS faithfulness (https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/): extract claims, check each is inferable from context, ratio supported/total. LLM-call per claim.
- SummaC (https://arxiv.org/abs/2111.09525): NLI at sentence granularity + aggregation, 74.4% balanced accuracy on six inconsistency datasets. Cheap, local, mediocre accuracy.
- MiniCheck (https://arxiv.org/abs/2404.10774): 770M FT5 checker reaches GPT-4-level on LLM-AggreFact at claimed ~400x lower cost. Best "cheap per claim" candidate; not tested on README/code/table content by the paper.
- SelfCheckGPT (https://arxiv.org/abs/2303.08896): sample N responses, inconsistency flags hallucination; no external source needed; needs multiple samples (here the gateway's variance becomes a signal). Tested on WikiBio only.
- Deterministic identifier/number claim extraction (versions, package names, URLs, flags): no paper found; standard practice is exact-match/regex against the pinned snapshot. Not found as a cited study.

## 3. Judge independence
- MT-Bench (https://arxiv.org/abs/2306.05685): GPT-4 judge >80% agreement with humans; documented position, verbosity, self-enhancement bias.
- Self-recognition (https://arxiv.org/abs/2404.13076): GPT-4/Llama 2 recognize own output; self-preference correlates linearly with self-recognition (causal evidence via fine-tuning).
- Self-preference as perplexity (https://arxiv.org/abs/2410.21819): GPT-4 favors lower-perplexity (familiar) text, regardless of authorship. Same-model reviewer is biased toward same-model prose.
- PoLL (https://arxiv.org/abs/2404.18796): panel of smaller judges from disjoint families beat one large judge on 3 settings/6 datasets, less intra-model bias, >7x cheaper.
- Huang et al. (https://arxiv.org/abs/2310.01798): LLMs cannot reliably self-correct reasoning without external feedback; sometimes worse. Argues against same-model review as the gate.
- JUDGE-BENCH (https://arxiv.org/abs/2406.18403): 11 LLMs vs 20 human-annotated sets; agreement varies widely by task; must be validated vs human labels before use.

## 4. Reproducibility
- Thinking Machines (https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/): temp 0, Qwen3-235B, 1000 samples x 1000 tokens -> 80 unique outputs (first divergence token 103); cause is lack of batch invariance (server load changes batch size), not atomics; batch-invariant kernels gave 1000/1000 identical, ~1.6x slower (26s vs 42s on Qwen3-8B, 55s unoptimised).
- vLLM batch invariance (search summary only; docs page 429 on fetch): beta, VLLM_BATCH_INVARIANT=1, seed via SamplingParams. Why a gateway ignores seed/temperature: not found in a primary source; likely a router/proxy not forwarding sampling params or a reasoning-model profile (hypothesis, unverified). Seed only seeds the sampler, so it cannot fix batch variance (tianpan.co 2026-06-02, secondary).
- OpenAI seed (cookbook https://cookbook.openai.com/examples/reproducible_outputs_with_the_seed_parameter, via search summary): "best effort", determinism not guaranteed, watch system_fingerprint.
- VCR.py (https://vcrpy.readthedocs.io/en/latest/): record HTTP once to cassette, replay later; record modes once/new_episodes/none/all (behaviour detail not read). pytest-recording URL I tried was 404.
- syrupy (https://github.com/syrupy-project/syrupy): snapshot == fixture; `--snapshot-update` is the explicit human-approval step; snapshots committed.
- Structured outputs: see section 1 (Anthropic). vLLM structured-outputs page not read (429).

## 5. Tools that keep human content / bound blast radius
- terraform-docs inject mode (search summary of guides, https://cdn.jsdelivr.net/gh/terraform-docs/terraform-docs@master/README.md): replaces only text between BEGIN_TF_DOCS/END_TF_DOCS; hand-written text outside untouched; missing markers => silent skip; `--output-check` fails CI on stale README. Best precedent for region ownership + deterministic drift gate.
- Mintlify (https://www.mintlify.com/library/how-to-stop-documentation-drift, vendor): agent finds affected pages, drafts, runs CLI validation, opens PR (or commits per setting), groups related fixes in one PR listing source PRs. Self-reported.
- ReadMe AI writer, Tessl docs-audit (search snippets only): PR-triggered, diff as source of truth, draft for human review.
- Swimm: coupling of docs to code snippets and CI drift flags (third-party directory only; primary not read).
- Doc Detective (https://docs.doc-detective.com/): executes commands/API calls/code blocks in docs and reports failures; GitHub Action behaviour not found on the page.
- Dependabot (https://docs.github.com/en/code-security/dependabot/working-with-dependabot/dependabot-options-reference): groups, open-pull-requests-limit (default 5), schedule, ignore bound PR volume; half the page unread.
- Not found: helm-docs, markdown-magic details; a study of LLM README regeneration loss rates.

## Ranked recommendations (impact on dependability / effort)
1. Unit-ID patch protocol: split source README into stable units (heading, paragraph, fenced code, table, list); LLM returns only ops per unit ID (keep / edit / drop+reason / insert); deterministic code copies kept units byte-for-byte and assembles. Fixes: "keep verbatim" not printed, silent loss (aider laziness result; lost-in-the-middle). Measure: verbatim-retention 100% by byte-compare; every source unit has exactly one disposition; non-edited-unit diff = 0. Risk: loses cross-unit coherence; edit ops on code/tables need a patch format the model follows (aider shows weaker models misuse diff formats), so keep a fallback of whole-unit replace.
2. Deterministic identifier gate: extract every version, package/import name, CLI flag, URL, number, code identifier from each new/edited claim and require exact (normalized) match in the pinned snapshot/fact store; fail closed. Fixes: wrong version/package names. Measure: seeded-fault detection recall (inject 50 wrong versions/names into known-good READMEs) >=95%; false-block rate on live READMEs. Risk: paraphrase and aliases cause false blocks; needs alias table.
3. Replace "cites a fact" with entailment: atomic-claim split (FActScore/RAGAS style), then pair each claim with the full cited fact text and run a small NLI/fact-checker (MiniCheck-FT5 or SummaC) locally; send only low-confidence claims to an LLM judge. Fixes: invented capabilities passing citation check (ALCE/Liu et al.: 50-75% citation precision/recall). Measure: precision/recall on a hand-labelled set of ~150 claims including mutated unsupported ones; target recall of unsupported claims >=90%. Risk: domain shift to code/table claims; atomic splitting errors; calibrate threshold.
4. Independent reviewer: run review on a different family (gpt-oss when authoring on qwen3-next, or vice versa), blind to authorship, ideally 2-3 judges with majority/any-fail for factual findings (PoLL). Fixes: non-independent reviewer, self-preference. Measure: agreement with human labels on a frozen holdout, false-accept rate on seeded defects, never tune prompts on the holdout. Risk: both models weak on long input; cost; disagreement handling.
5. Record/replay + golden snapshots: cache every gateway call by hash(model, params, prompt, input revision) in cassettes; the authored plan/section is a stored artifact; rerun replays with zero provider calls; human approves changes via explicit snapshot update. Fixes: reruns differ (seed ignored; batch variance is the real cause per Thinking Machines). Measure: rerun with unchanged inputs is byte-identical and makes 0 calls; cassette miss on changed input only. Risk: stale cassettes hide regressions; need a deliberate re-record job.
6. Region ownership and diff budget: markers or unit ownership for generated vs inherited regions (terraform-docs pattern); gate on "lines changed in locked units = 0" and cap total change size per PR, grouping like Dependabot. Fixes: blast radius, silent rewrites. Measure: unintended-line changes per PR = 0; median PR size. Risk: markers in human READMEs are intrusive, prefer unit-hash ownership kept outside the file.
7. Defect-injection harness for validators and reviewer: automated mutation of candidate READMEs (drop a unit, change a version, add an invented feature) must be caught; run in CI. Fixes: unmeasured checker quality. Measure: per-defect-class recall tracked over time. Risk: synthetic defects easier than real ones; keep a corpus of real past failures.
8. Constrained output for plan/decision JSON (vLLM structured outputs, if the gateway forwards them; unverified) plus deterministic check that dispositions cover all unit IDs. Fixes: malformed or partial plans. Measure: schema-invalid rate 0; coverage 100%. Risk: constrained decoding gives validity not truth; gateway may not support it. Optional later: SelfCheckGPT-style multi-sample agreement on high-risk claims only.
