## 3. The ROLLBACK claim: "a reverted version bump returns candidates to VALID_UPDATE_AVAILABLE and never INVALIDATED"

Tested with `bundle/evaluation.evaluate` and `bundle/invalidation.route` on a real `dependencies.json` (rb.py):

| Change | Dependency class | Result |
|---|---|---|
| VALIDATOR_VERSION / any BC version | `validators` | VALID_UPDATE_AVAILABLE |
| NORMALISATION_VERSION | `components.normalisation` | VALID_UPDATE_AVAILABLE |
| RENDERER_VERSION | `components.renderer` | VALID_UPDATE_AVAILABLE |
| REVIEWER_LOGIC_VERSION | `components.reviewer_logic` | VALID_UPDATE_AVAILABLE |
| INHERITED_UNITS_VERSION / EXTRACTOR_VERSION alone | `environment.*` (VERSION_PROXIES) | VALID_UPDATE_AVAILABLE |
| one fact record altered, or one added (`package:published_version`) | `facts` | **INVALIDATED** |

- Comparison is `!=` (`evaluation._differs`, `_flatten`), symmetric: a candidate sealed under version N+1 and evaluated by code at N differs the same way as the forward direction. So the claim holds in both directions for the first five rows.
- It fails for any bump that changes fact records. None of the 30 stored bundles has `consumed_fact_ids` (counted: 0 of 30), so the "only cited facts count" narrowing does not apply and any added, removed or altered fact record yields `facts` scope and INVALIDATED. C2's mandatory `package:published_version` fact (new record) and C3's INHERITED_UNITS_VERSION bump (regenerated unit records; docs/investigations/13 section 6.4 recorded 24 of 30 routed to INVALIDATED for a 1 to 2 bump) both hit this. Reverting such a bump after candidates were re-extracted flips records again, so the revert also invalidates.
- Wording: `recheck.py` never changes a manifest state; its currencies are CURRENT, RECHECKED_CURRENT, UPDATE_OPTIONAL, UPDATE_REQUIRED, UNVERIFIED. For the extraction scope, "an extractor-version difference is UNVERIFIED" and regenerated inherited units that differ give UPDATE_REQUIRED. `COUNTED_STATES = {"READY_FOR_PROPOSAL"}` (`core/candidates.py:49`) and `load_proposable_candidate` (`:595`) refuse a VALID_UPDATE_AVAILABLE bundle, so a rollback "returns" candidates to a state that is not counted and not proposable until rechecked or resealed.
- Order of governed bumps: C2 (VALIDATOR, EXTRACTOR), C3 (NORMALISATION, INHERITED_UNITS, VALIDATOR), C5 (RENDERER), C6 (REVIEWER_LOGIC). Each is one constant and one card; the constants are separate, so a partial revert of one card does not touch another's, provided the C2/C3 constants are not both in the same commit.
